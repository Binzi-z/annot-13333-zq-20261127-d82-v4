题面见 task/PROMPT.txt。仓库附本地合成输入及其格式检查。

## buildcheck：构建声明与读记录核对工具

纯 Python 3.12 标准库实现，面向离线缓存场景：子任务曾把平台标记写进产物，
而缓存只按源码命中。工具先推导指定输出的输入闭包，再比对每个动作实际
消费的摘要，给出三态判定并指出最短的漏声明依赖链。

```
buildcheck/
  paths.py      Windows 逻辑路径规范化（根/大小写/词法化简）+ 抽象重解析点
  model.py      分类输入（源文件/工具/平台/公开环境槽）、动作、声明、世界状态
  closure.py    输入闭包推导（BFS、断环、平台相关性标注、规范摘要）
  simulator.py  读记录模拟器（支持漏声明/缓存替换/记录缺失故障注入）
  checker.py    核对器：摘要比对、三态判定传播、最短漏声明链、增量重判
  verifier.py   对照验证器：全量重算 + 迭代 DFS 遍历
  fixtures.py   夹具：公共生成器、断环、缓存替换、十万条不相关依赖
  __main__.py   演示入口
```

判定语义：

- `shareable` 可共享缓存：实际消费全部已声明且摘要一致；
- `must_invalidate` 必须失效：摘要不一致、消费未声明输入或上游已失效；
- `no_authority` 无权作判定：读记录缺失/被不透明缓存结果替换/路径落在
  不可解析的重解析节点下。

关键性质：

- 仅改变平台 → 平台无关子树整体复用（增量重判不读任何读记录）；
- 同名工具换字节 → 所有相关后继失效；
- 重排声明、合并相同子图 → 闭包摘要与判定稳定；
- 核对器按需推导（10 万条不相关依赖下仅十几次查询），验证器全量重算对照。

运行：

```
python -m unittest discover -s tests   # 31 个测试
python -m buildcheck                   # 场景演示
```
